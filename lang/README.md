# Mycel

A friendly, typed programming language for your first program and your hundredth. It compiles to sandboxed
JavaScript and runs on Node (no runtime dependencies). Programs run with `mycel`; packages install with `ply` (like
Python's `pip`). Source files are `.myc`; `.olx` files work everywhere too. (Mycel was called Ply until 2026-11-06.)

```mycel
print("hi")
```

That is a whole program. A bigger one:

```mycel
enum Shape { Circle(r: Float), Rect(w: Float, h: Float) }

fn area(s: Shape) -> Float {
  return match s {
    .Circle(r) => 3.14159 * r * r
    .Rect(w, h) => w * h
  }
}

for s in [Shape.Circle(r: 1.0), Shape.Rect(w: 2.0, h: 3.0)] { print(f"{area(s):.2f}") }
```

* **Readable from any first language.** Python's `and`/`or`/`not`, `print(a, b)`, f-strings and `for i, x in xs`
  work as-is; habits from Python, JS/TS, Java, Go, Rust and Swift that don't fit get an error naming the habit and the
  Mycel spelling ("`elif` is Python — Mycel writes `else if`"); see `docs/HABITS.md`.
* **Safe types without ceremony.** `let`/`var`, inference, optionals (`T?`), `Result<T, E>` with `?`, enums with
  payloads and exhaustive `match`, generics, classes/structs/interfaces, extensions, generators, `async`/`await`.
* **Errors that say what to type.** Every error says what, where, why and how to fix it, in text and as JSON
  (`mycel check --json`: `code`, `line`, `col`, `message`, `why`, `suggestion`).
* **Safe to run untrusted code.** A program with no grants is pure. File system, network, processes and environment
  variables are *capabilities* the host grants per run (path allow-lists, host allow-lists). Hard limits: steps, wall
  time, output size, collection/string size, abort signal; `runIsolated` adds a real heap cap and a kill switch.

## Install and use

Requires Node 24+. There is no global install; run from the repository:

```sh
cd lang
npm install             # TypeScript and Node types are development dependencies only
npm run build            # tsc → dist/ (bin/mycel builds on first use too)
bin/mycel --version      # mycel 0.1.0
```

```sh
bin/mycel new shop && cd shop      # project: ply.json, src/main.myc, tests/
../bin/mycel run                   # runs src/main.myc  (or: mycel run file.myc -- arg1 arg2)
../bin/mycel test                  # every  test "name" { ... }  block in src/ and tests/
../bin/mycel check --json          # type-check only, diagnostics as JSON
../bin/mycel fmt                   # canonical formatting (idempotent; --check for CI; --fix rewrites old "${x}")
../bin/mycel build                 # build/shop.js, runs with: node build/shop.js
../bin/mycel doc --out=docs        # Markdown from signatures and /// comments
../bin/mycel repl                  # interactive session (:type, :reset, :help)
../bin/ply add mathx               # packages: add / remove / install / publish (local registry, ply.lock with sha256)
```

Permissions are explicit: `mycel run app.myc --allow-read=data --allow-write=data --allow-net=api.example.com
--allow-listen --allow-run=git --allow-env=HOME` (`-A` grants everything). A project's `ply.json` can list
`"capabilities"` for `mycel run`/`mycel test`. Limits: `--max-steps= --max-seconds= --max-output= --isolated --max-memory-mb=`.

## Windows alpha

A private Windows x64 standalone build is staged by `release/build-windows.mjs`
and `release/package-windows.mjs`; it needs no separate Node installation.
It is **untested on real Windows until private CI runs**. See
`release/WINDOWS.md` for build, verification and publication requirements.
After owner review and publication, the PowerShell install command is:

```powershell
irm https://ol1x.xyz/mycel/install.ps1 | iex
```

It installs per user into `%LOCALAPPDATA%\Mycel\bin`, verifies the ZIP's
SHA-256 and adds that directory to the user PATH. For a source checkout on
Windows with Node 24 installed, use `bin\mycel.cmd` and `bin\ply.cmd`
(or `node bin/mycel` and `node bin/ply`).

## Documents

* `docs/SPEC.md` — the language specification (syntax, types, semantics, errors, modules).
* `docs/stdlib/*.md` — standard library reference, generated by `mycel doc` from `std/*.olx` (`ui`, `db`, `files`, `time`, `web`, `json`, etc.).
* `docs/EMBEDDING.md` — the host API (`run`, capabilities, limits, native modules) and the olx embedding proposal.
* `STATUS.md` — implemented / tested / partial / planned, and the next step.
* `examples/` — `tour/` (one file per topic), and applications: `calc/` (lexer + parser + evaluator),
  `todo/` (JSON on disk, args), `api/` (REST server and client), `guestbook/` (web app with `std.web`),
  `notes/` (database + file export/import with `std.db` and `std.files`).

## Layout

`src/` lexer → parser → checker (types, patterns, exhaustiveness) → codegen → runtime/natives/stdlib → host (`run`,
`runIsolated`) → cli; `std/` the prelude and standard modules *written in Mycel* with `extern` declarations bound to
natives; `tests/` (`npm test`, 90+ tests incl. hostile, fuzz and sabotage-checked cases).

`ply run`, `ply check` and `ply test` stay as aliases of the `mycel` commands (old scripts and IDE run configs keep
working); `ply.json` / `ply.lock` / `ply_modules/` keep their names because they belong to the package manager.
